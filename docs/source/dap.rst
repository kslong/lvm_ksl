Spectral fitting: Using the DAP
===============================

The LVM Data Analysis Pipeline (LVM-DAP) fits each fiber spectrum with a
stellar population model (RSP) plus a set of parametric and
non-parametric emission-line measurements. It is a separate tool
(``lvmdap``/``lvm-dap-conf``) from the ``lmfit``-based line fitters
described in :doc:`spectral_fitting_local` -- use LVM-DAP when you need the
stellar continuum decomposition or the DAP's own emission-line tables;
use :doc:`spectral_fitting_local` when you only need fast Gaussian fits to a
handful of known lines.

This page covers the ``lvm_ksl`` tools that wrap that workflow:

- ``GetDAP.py`` -- download the DAP output already produced for an
  exposure as stored at Utah
- ``RunDap.py`` -- run LVM-DAP yourself, on any FITS spectrum, without
  hand-wiring a new run directory each time
- ``DAP2tab.py`` / ``DAPGauss2tab.py`` -- turn a DAP output FITS file
  (from either source above) into a simple, analysis-ready table
- ``ListDapLines.py`` -- list every emission line a DAP output file was
  configured to fit, for comparing against or regenerating
  ``data/dap_lines.txt``


Overview
--------

A DAP output file (``dap-<config>-<expnum>.dap.fits.gz``) is a
multi-extension FITS file: a per-fiber summary table (stellar
population fit, extinction, redshift, ...) plus several emission-line
extensions that are inconvenient to work with directly. The typical
workflow is:

1. **Get a DAP output file**, either the official one from Utah
   (``GetDAP.py``) or by running LVM-DAP yourself on a spectrum you
   already have (``RunDap.py``).
2. **Flatten it into a table** with ``DAP2tab.py`` and/or
   ``DAPGauss2tab.py``, whose column-naming convention (``flux_<name>``,
   ``fwhm_<name>``, ``wave_<name>``, ...) matches the tables produced by
   ``lvm_gaussfit.py``/``sky_gaussfit.py`` in :doc:`spectral_fitting_local`.


Retrieving the Official DAP Output -- GetDAP.py
------------------------------------------------

Downloads the DAP output file(s) already generated by the pipeline run
at Utah for one or more exposures, using ``sdss_access`` (so a
``.netrc``-based login is required -- see :doc:`data_retrieval` for the
same authentication path used by ``GetFromUtah.py``).

**Usage**::

    GetDAP.py [-h] [-no_cp] [-drp VERSION] filename.txt
    GetDAP.py [-h] [-no_cp] [-drp VERSION] mjd expstart [expstop]

**Options:**

-h
    Print help and exit.

-drp VERSION
    DRP version used to locate the DAP files (default: ``1.2.1``).

-no_cp
    Skip copying each retrieved DAP file into a local ``./DAP``
    directory; by default it is copied there in addition to being left
    in the ``SAS_BASE_DIR``-mirrored location ``sdss_access`` downloads
    it to.

**Arguments:**

filename.txt
    An ASCII table (read with ``astropy.io.ascii``) with one row per
    exposure and columns ``mjd``, ``expnum``, and (optionally)
    ``tileid``. If ``tileid`` is present it is used directly; if not,
    it is looked up automatically (see below).

mjd, expstart, expstop
    Alternative to the table form, matching ``GetFromUtah.py``'s
    convention: retrieve a range of exposures from a single MJD
    directly from the command line. ``expstop`` defaults to
    ``expstart``.

**Output:**

Each DAP file is written to ``./DAP/dap-rsp108-sn20-<expnum>.dap.fits.gz``.

**Notes:**

- The DAP configuration string is fixed at ``rsp108-sn20`` (matching the
  convention assumed by ``DAP2tab.py``/``DAPGauss2tab.py``) as a
  module-level constant (``DAP_CONFIG``), so edit the source if you
  need a different one.
- Requires ``SAS_BASE_DIR`` to be set, matching the other retrieval
  tools in :doc:`data_retrieval`. If it points at a location that
  doesn't currently exist (e.g. an unmounted external drive), a clear
  error is printed instead of the raw traceback ``sdss_access`` itself
  would raise.
- Unlike ``GetFromUtah.py``, this script needs an *exact* tileid (not a
  wildcard) to build its download path. When one isn't supplied by the
  table's ``tileid`` column, it's resolved automatically via
  ``GetFromUtah.resolve_tileid()`` -- a read-only remote listing, one
  extra network round-trip per exposure. The table form is faster if
  you already know the tileids.


Running Your Own DAP Fit -- RunDap.py
---------------------------------------

Wraps ``lvm-dap-conf`` (the LVM-DAP command-line fitter, installed from
the separate ``lvmdap`` package) so a fit can be launched from any
directory with a single command, instead of hand-copying a yaml config
and symlinks into every new run directory.

**Usage**::

    RunDap.py [-h] [-force] [-template file] [-config name] [-out label] fits_file

**Options:**

-h
    Print help and exit.

-force
    Regenerate the yaml config from the template even if one already
    exists in the current directory. By default an existing config is
    left untouched, so hand-tuned parameters from a previous run
    survive.

-template file
    Use a yaml template other than the bundled
    ``data/dap_ref/ksl-dap_v110.template.yaml``.

-config name
    Name the generated config file something other than the default
    ``ksl-dap_v110.yaml``.

-out label
    Root name for the files ``lvm-dap-conf`` creates (the same label
    the DAP normally takes as a positional argument). If omitted,
    defaults to ``fits_file``'s basename with any directory and
    ``.fits``/``.fits.gz`` suffix stripped, e.g.
    ``xdata/foo/whatever.fits`` becomes ``whatever``.

**Arguments:**

fits_file
    Input FITS spectrum, with or without a ``.fits`` suffix; may be a
    relative path.

**Prerequisites:**

- The ``lvmdap`` package must be installed (``pip install`` or
  ``pip install -e .`` against a local clone) so that ``lvm-dap-conf``
  is on your ``PATH``. Reinstalling with ``-e`` is required if you edit
  the ``lvmdap`` repo itself -- otherwise a separately pip-installed
  copy is what actually runs.
- The environment variable ``LVM_DAP`` must point at the ``lvmdap``
  installation directory, i.e. the one containing its ``_legacy``
  subdirectory (line lists, masks, and the ``auto_ssp_LVM.config`` fit
  configuration).

**What it does:**

Run from the directory you want the outputs in. On first run it
creates, in the current directory:

- ``output_dap/`` -- where the DAP writes its output FITS/plots
- ``_legacy`` -- a symlink to ``$LVM_DAP/_legacy``, required because
  ``auto_ssp_LVM.config`` itself references bare paths like
  ``_legacy/Ha_LVM.config`` that ``lvm-dap-conf`` opens relative to the
  current working directory
- ``ksl-dap_v110.yaml`` (or the name given by ``-config``) -- generated
  from the template with ``output_path`` (must be absolute -- a
  relative value silently corrupts, writing under a bogus path rooted
  at ``/``) and ``lvmdap_dir`` filled in

It then runs ``lvm-dap-conf <fits_path> <label> <config_name>``,
streaming its output directly, and exits with its return code.

**Example**::

    mkdir myfit && cd myfit
    RunDap.py ../xdata/lvmSFrame-00012345.fits

    # rerun with a different label, keeping the same config
    RunDap.py -out rerun1 ../xdata/lvmSFrame-00012345.fits

**Changing fit parameters:**

Edit ``data/dap_ref/ksl-dap_v110.template.yaml`` once (RSP file,
``w-range``, redshift/sigma/AV search bounds, emission-line list,
etc.) to change parameters for all future runs; pass ``-template`` to
use a one-off alternative without touching the shared default.


Post-Processing DAP Output into User-Friendly Tables
------------------------------------------------------

A raw DAP output file is a multi-extension FITS file that is awkward to
work with directly. ``DAP2tab.py`` and ``DAPGauss2tab.py`` each flatten
one or more DAP files into a single ascii table, one row per fiber,
using the same column-naming convention (``flux_<name>``,
``eflux_<name>``, ``wave_<name>``, ``fwhm_<name>``, ...) as
``lvm_gaussfit.py``/``sky_gaussfit.py`` (see :doc:`spectral_fitting_local`).
They differ in which DAP extension they read:

DAP2tab.py
^^^^^^^^^^

Reads the DAP's **non-parametric** emission-line extensions
(``NP_ELINES_B``/``NP_ELINES_R``/``NP_ELINES_I`` -- direct-integration
flux measurements split by wavelength channel), joined onto the
per-fiber ``PT`` summary table, for a fixed set of 37 lines useful for
SNR spectroscopy (H I Balmer series H\ :math:`\alpha`--H\ :math:`\epsilon`,
He I, He II, and the forbidden lines [NeIII], [OI]--[OIII], [NI], [NII],
[SII], [SIII], Ca II, [CaII], [FeII], [FeIII], [FeV], [FeX], [NiII]) --
see the line-name table below.

**Usage**::

    DAP2tab.py [-h] filename(s)

**Arguments:**

filename(s)
    One or more DAP output FITS files (any argument containing
    ``fits`` is treated as an input file).

**Output:**

``DAPsum_<root>.txt`` per input file (``ascii.fixed_width_two_line``),
where ``<root>`` is the exposure number extracted from the input
filename.

**Line names:**

Output columns are named ``flux_<name>``/``eflux_<name>``/``wave_<name>``/
``fwhm_<name>``/... where ``<name>`` is the ``gauss_name`` below.
Doublets/multiplets from the same ion use ``_a``/``_b`` (shorter
wavelength first); a line with no close partner in this set instead gets
a truncated-wavelength suffix, or no suffix at all when the DAP name

DAPGauss2tab.py
^^^^^^^^^^^^^^^^

Reads the DAP's **parametric** (single-Gaussian) emission-line
extension (``PM_ELINES``), for its own fixed set of 13 of the strongest
lines ([OII] doublet, H\ :math:`\beta`, [OIII] doublet, [OI], [NII]
doublet, H\ :math:`\alpha`, [SII] doublet, [SIII] doublet) -- a smaller,
independent list, not automatically kept in sync with ``DAP2tab.py``'s.

**Usage**::

    DAPGauss2tab.py filename(s)

**Output:**

``DAP_PME_<root>.txt`` per input file, same table format as
``DAP2tab.py``.

**Units caution:**

Both scripts convert DAP flux values to **physical** units
(erg/s/cm\ :sup:`2`) by multiplying by ``1e-16`` before writing the
output table. This is different from ``lvm_gaussfit.py`` and
``sky_gaussfit.py`` (:doc:`spectral_fitting_local`), whose ``flux_*`` output
columns retain the ``x1e16``-scaled convention and must be divided by
``1e16`` to get physical values. Do not apply that same division to
tables produced by ``DAP2tab.py``/``DAPGauss2tab.py`` -- they are
already physical.

**Example**::

    DAP2tab.py DAP/dap-rsp108-sn20-00012345.dap.fits.gz
    DAPGauss2tab.py DAP/dap-rsp108-sn20-00012345.dap.fits.gz


Reference: All Lines the DAP Can Fit -- data/dap_lines.txt
-------------------------------------------------------------

``DAP2tab.py`` only extracts a fixed set of 37 named lines (``DAPGauss2tab.py``
fewer still). The DAP itself fits far more: every ``NP_ELINES_B``/``_R``/``_I``
extension column named ``flux_<name>``/``e_flux_<name>``/... corresponds
to one fittable line, and there are 215 of them across the three arms.

``data/dap_lines.txt`` lists all 215, generated by reading the
``e_flux_*`` column names out of an example DAP file's three
``NP_ELINES_*`` extensions. Columns:

Arm
    ``B``, ``R``, or ``I`` -- which arm's extension the line comes from.

Ion
    The ion/species name as the DAP names it (e.g. ``[OIII]``,
    ``Halpha``).

LineID
    Display label; currently a copy of ``Ion`` for every row, but a
    separate column so display labels can be hand-edited later (to
    disambiguate or shorten) without touching the physical ``Ion`` ID.

Wave_air, Wave_vac
    Air and vacuum wavelength in Å. DAP line wavelengths are **air**
    (confirmed by comparing several well-known lines' DAP values against
    a vacuum-to-air conversion -- agreement to within ~0.05 Å, versus
    ~1-2 Å off for vacuum); ``Wave_vac`` was added via the standard
    air-to-vacuum conversion (Morton 2000 / IDL ``astrolib``
    ``airtovac.pro`` formula).

DAP_name
    The exact ``<Ion>_<wavelength>`` string the DAP itself uses as a
    column-name suffix -- pass this as ``get_one_line()``'s ``name=``
    argument if extending ``DAP2tab.py``'s hardcoded line set.

.. note::
   The ``[SIII]`` wavelengths in this table (6312.06, 9069.00, 9531.10
   Å, air) are the DAP's own values and do **not** match the currently
   accepted values used in Mappings or Cloudy. Treat them as the DAP's
   internal convention, not as authoritative atomic data, until
   corrected.

This table is also the default line-overlay source for
``PlotSpecI.py`` (see :doc:`spectrum_plots`).

Regenerating/checking the table -- ListDapLines.py
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

``data/dap_lines.txt`` is a transcription of one DAP run's column names,
not atomic physics -- the DAP's input yaml configuration controls which
lines it fits, so a different config can add, drop, or shift lines.
``ListDapLines.py`` rebuilds the same table from any DAP output file, so
it can be diffed against ``data/dap_lines.txt`` after a yaml change
rather than assuming the checked-in table is still current.

**Usage**::

    ListDapLines.py [-h] [-out dap_lines.txt] dapfile

**Options:**

-h
    Print help and exit.

-out file.txt
    Output path (default: ``./dap_lines.txt`` in the current directory).
    Deliberately never defaults to ``data/dap_lines.txt``, so a run can't
    silently overwrite the checked-in table -- compare the two and copy
    over by hand if the new one should replace it.

**Arguments:**

dapfile
    A DAP output FITS file (``.fits`` or ``.fits.gz``).

**What it does:**

For each of ``NP_ELINES_B``/``NP_ELINES_R``/``NP_ELINES_I`` present in
``dapfile``, every ``e_flux_<Ion>_<Wave_air>`` column names one fitted
line (the same convention ``DAP2tab.py``'s ``get_lines()`` reads).
``Wave_vac`` is computed with the same Morton 2000 air-to-vacuum formula
used to build the original table, and the ``[SIII]``-legacy-value note
above is regenerated dynamically from whatever ``[SIII]`` wavelengths
that run actually has, rather than hardcoded.


Typical Workflow
-----------------

Using the official Utah-produced DAP output::

    # 1. Retrieve the DAP file for a set of exposures
    GetDAP.py exposures.txt

    # 2. Flatten it into a simple table
    DAP2tab.py DAP/dap-rsp108-sn20-00012345.dap.fits.gz

Running your own DAP fit on a spectrum you already have::

    # 1. Run the DAP in its own output directory
    mkdir myfit && cd myfit
    RunDap.py ../xdata/lvmSFrame-00012345.fits

    # 2. Flatten the resulting output into a table
    DAP2tab.py output_dap/whatever.output.fits.gz
    DAPGauss2tab.py output_dap/whatever.output.fits.gz


Notes
-----

- LVM-DAP itself (the ``lvmdap`` package and ``lvm-dap-conf``) is a
  separate codebase from ``lvm_ksl``; these tools only wire up and
  consume it.
- ``RunDap.py`` leaves an existing yaml config untouched on rerun, so
  hand-tuned parameters for a specific run directory survive; use
  ``-force`` to regenerate from the shared template.
- See :doc:`spectral_fitting_local` for the ``lmfit``-based alternative when
  you don't need the DAP's stellar continuum fit.
